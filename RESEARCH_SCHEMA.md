# Zone Engine Shadow Research Schema v1

Research telemetry is observational only. It does not gate or modify production entries.

## Files

- `data/zone_observations.jsonl` — one record per research observation boundary: `SIGNAL_CREATED`, `TOUCH_BLOCKED`, `TOUCH_REJECTED`, `TOUCH_STALE`, `ACTIVATION_BLOCK`, `REARM`, `NEAREST_APPROACH`.
- `data/entry_decisions.jsonl` — execution decision lineage: deduplication, execution gates, cycle cap, claim, execution result.
- `data/market_bars_1h.jsonl` — closed 1H bars needed to reproduce feature context and forward outcomes.
- `data/market_bars_5m.jsonl` — closed 5M bars needed for forward outcome reconstruction.
- `data/research_bar_cursors.json` — per symbol/timeframe/provider persistence cursor. Append happens before cursor advancement so a cursor failure can duplicate data but cannot silently discard the written bars.
- `data/research_manifest.json` — schema version, last scan/code revision, effective runtime config and persistence counters.
- `data/research_persistence_errors.jsonl` — fail-open persistence errors with path, symbol, exception type and message.
- `data/research_outcomes.jsonl` — matured 24h forward outcomes generated by `research_forward.py`.
- `data/research_outcome_state.json` — idempotency state for matured outcome records.
- `data/market_context.jsonl` — decision-time public market snapshots for signal boundaries (funding, OI, mark/index, book depth/imbalance and recent public trades). This is observational only and never gates trading.
- `data/account_context.jsonl` — one best-effort private account snapshot per scan (equity, available/used/freezed margin, realized/unrealized profit, balance, positions, recent fills/fees and forced-close activity). This is observational only and never gates trading.

## Identity

- `zone_id` is stable across rolling DataFrame windows because it uses zone origin timestamp and geometry. `provider` is stored on observations and bars so forward outcomes never mix venues when the same symbol has data from more than one provider.
- `bar_id` is deterministic from symbol, timeframe, timestamp and provider.
- `observation_id` is deterministic from event type, symbol, direction, zone identity, observation timestamp and visit identity.
- `decision_id` is deterministic from scan, event, stage, reason and attempt identity.

## Shadow feature families

Each zone observation records, when available:

- zone age in bars and hours;
- zone width and width as a percentage of reference price;
- distance to midpoint;
- penetration depth;
- body/range, wick ratios, close location and range percentage;
- 5M trigger-volume ratio versus the previous 20 closed 5M bars (`volume_ratio_5m20`);
- touch count before trigger;
- structural room in R;
- current directional-candle result;
- shadow directional-candle candidate rule (body >= 30% of range and close near the directional extreme);
- shadow structure-room candidates: 0.5R, 1.0R, 1.2R, 1.5R;
- shadow zone-age candidates: 24h, 48h, 72h;
- shadow volume candidates: 0.8x, 1.2x, 1.5x;
- shadow penetration candidates: <=20%, <=50%;
- 1H returns over 1h/3h/6h/12h/24h;
- 4H return and EMA50/EMA200 context built only from complete 4H candles;
- 5M returns over 5m/15m/30m/1h/3h/6h/12h/24h when sufficient history is available;
- 5M EMA20/EMA50 distance and one-bar slope, ATR% and recent return volatility;
- approach-to-zone return/speed/range and consecutive directional-bar streak strictly before the trigger bar;
- EMA50/EMA200 distance and available EMA trend direction.

Funding, OI, CVD, FVG, liquidity sweeps, BTC context and session state are intentionally not production filters and are not fabricated when unavailable.

## Market context fields

`market_context.jsonl` preserves raw decision-time inputs so later research can derive rolling measures without inventing history. Observations explicitly record whether rich context was `PERSISTED`, `PERSISTENCE_FAILED` or `NOT_COLLECTED`, so a missing market snapshot is never mistaken for a measured zero.

- premium/index: `mark_price`, `index_price`, `mark_index_basis_pct`, `funding_rate`, `next_funding_time_ms`;
- OI: `open_interest`, `open_interest_ts`; historical OI changes and funding z-scores should be derived only from earlier snapshots for the same symbol/provider;
- book: `best_bid`, `best_ask`, `spread_pct`, top-5/top-10 quantity and quote depth, quote imbalance, microprice, depth within 0.1%/0.5%/1%;
- public trades: valid count, buy/sell aggressor quote, aggressor delta, buy ratio, price range, first/last trade timestamp, sample span and average trade notional.

These fields are observational only. No funding, OI, order-book or flow value is used as a production gate.

### Nearest-approach cost control
Nearest-approach observations remain enabled as cheap analytical boundaries, but the expensive four-endpoint BingX microstructure snapshot is disabled for nearest-only boundaries by default (`RESEARCH_CONTEXT_NEAREST_APPROACH=false`). Rich market context is collected by default for `SIGNAL_CREATED` boundaries; rejected-touch/rearm boundaries keep the full OHLCV-derived research feature set but do not delay the trading cycle with extra private/public context requests unless `RESEARCH_CONTEXT_FOR_REJECTIONS=true` is explicitly enabled. This keeps observational enrichment from changing production execution timing.

## Account context

`account_context.jsonl` is captured at most once per scan to avoid per-symbol private API bursts. A successful snapshot records `account_context_id`, `captured_at`, account asset/balance/equity, `available_margin`, `used_margin`, `freezed_margin`, `unrealized_profit`, `realized_profit`, available maker/taker commission rates, a sanitized list/aggregate of currently open positions (side, size, entry/mark, liquidation price, leverage, unrealized PnL and notional), and a recent account-activity window containing actual fills with `trade_id`, `order_id`, fill price/qty, realized PnL and fee; fund-flow records by `income_type` including realized PnL, funding fees and trading fees; plus recent forced-close/liquidation/ADL events. The activity window is 15 minutes by default and intentionally overlaps across scans so fill/fund-flow history can be deduplicated later by `trade_id`/`tran_id`. If the private endpoint is unavailable, the observation is explicitly marked `persisted=false`; missing account context is never replaced with an assumed value.

## Forward outcomes

`research_forward.py --write` labels only bars whose completed `close_time` is strictly after the observation timestamp. A 24h outcome is written only after a complete 24h 5M path is available without missing intervals; otherwise the observation remains pending/censored.

For each matured observation the script calculates forward close returns at 5m/15m/30m/60m/3h/6h/12h/24h using the latest completed 5M close at or before each horizon (with a `*_sample_ts` field); this is a bar-close approximation and never uses a post-horizon close. MFE/MAE are calculated at 15m/30m/60m/3h/6h/12h/24h only when the full post-observation path is complete, and time-to-favorable/adverse thresholds is bounded to the first 24h.

For `SIGNAL_CREATED` the result is a forward outcome for the generated opportunity. For rejection/block/approach/rearm observations the result is `HYPOTHETICAL_FORWARD_OUTCOME`.

Missing future bars or gaps are reported as censored rather than imputed; incomplete MFE/MAE paths are not treated as complete outcomes.

### Observation timing
`source_event_ts` is the trigger/touch event time. `observation_ts` is the decision-time timestamp used for feature availability and forward-path anchoring.

### Shadow volume
`volume_ratio_5m20` uses the trigger bar volume divided by the mean volume of the previous 20 closed 5m bars; it is not compared with 1H volume. This is a shadow feature only and does not gate production entries.

### Market bar timing
Each persisted market bar includes `close_time`; only fully closed bars are persisted. Forward MFE/MAE and target timing use completed bars so an in-progress candle cannot leak into the outcome horizon.

### Timing and leakage controls
`source_event_ts` is the original trigger/touch/rearm/approach time. `observation_ts` is the decision-time timestamp used to define feature availability and the forward horizon. Higher-timeframe features use only fully closed 1H bars available by `observation_ts`.

`volume_ratio_5m20` uses the trigger 5m bar volume against the previous 20 closed 5m bars. Persisted market bars include `close_time`, and forward MFE/MAE/time-to-threshold calculations use completed bars only.
