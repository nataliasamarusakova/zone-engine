## Изменения

- Финальная проверка позиций (`update_active_trades`) и reconciliation выполняются после исполнения и сохранения scan summary, но **до** длительного flush исследовательских журналов.
- Tracker использует успешный общий `get_positions` snapshot только для первой проверки позиции каждой сделки. Проверки исполнения TP, чтение позиции после TP и заключительная проверка позиции остаются свежими запросами. При сбое/некорректном ответе общего запроса выполняется прежний per-symbol fallback.
- Размер отложенной исследовательской пачки по умолчанию повышен с 8 до 32 (допустимый диапазон остаётся 4–32). Для 327 строк это должно уменьшить число batch-контекстов примерно с 41 до 11; реальный выигрыш времени надо измерить по следующему Actions-run.
- Торговые сигналы, построение зон, параметры SL/TP, правила BE, условия открытия сделки, universe сканирования, workflow schedule и файлы `data/` не менялись.

## Важные ограничения

- В этом контейнере нет Python 3.11, который используется GitHub Actions. Тесты прогнаны на Python 3.13.5.
- Не запускался GitHub Actions job, BingX VST не подключался, фактический runtime выигрыш не измерен.
- Изменения не отправлены в GitHub и не применены автоматически к удалённому `main`. Перед установкой нужно наложить diff на точный текущий commit `main`, проверить конфликты, запустить Python 3.11 tests и затем контролируемый workflow.
- Текущий workflow всё ещё может превышать интервал cron/dispatch: этот патч сокращает повторные позиции и research batching, но не обещает runtime меньше пяти минут без нового измерения.
