# Zone Engine — исходный пакет без runtime `data/` (18 октября 2026)

Этот архив предназначен для аудита и подготовки обновления Zone Engine 5.48.13. Он содержит исходный код, workflow GitHub Actions, тесты, runbook и проверяемый recovery seed для исследовательской истории. Корневой каталог `data/` намеренно исключён: пакет не содержит текущих открытых позиций, торговых журналов и runtime-состояния.

**Не распаковывайте этот пакет поверх действующего репозитория без предварительного diff.** Снимок не был побайтно сверён с актуальной удалённой веткой GitHub `main`; включённые файлы нельзя автоматически считать точным состоянием удалённого репозитория. Перед применением нужно получить текущий `main`, сопоставить diff и сохранить runtime `data/`.

## Что вошло в текущую итерацию

- Оптимизация отдельных операций чтения/сканирования и исследовательского сбора данных; фактическую экономию времени должен подтвердить следующий реальный Actions-run.
- Проверка свежести 5m-триггера непосредственно перед отправкой рыночной заявки.
- Восстановление исследовательской истории из упакованных проверяемых seed-файлов.
- Межзапусковое восстановление архива compaction/retention из артефактов GitHub Actions с проверкой workflow/ветки/успешного состояния запуска.
- Fingerprint-based policy, чтобы не загружать неизменившийся cumulative retention artifact каждый цикл: повторная загрузка нужна при изменении данных либо по безопасному 45-дневному refresh.
- Защитные условия, чтобы при недоступном или потерянном архиве не выполнять новую compaction, способную навсегда удалить исторические строки без сохранённой копии. Если upload после успешной compaction не удался, workflow валидирует pre-compaction snapshots и восстанавливает исходные журналы перед commit.
- Дополнительный fail-closed commit gate: если size-guard сработал, отсутствие корректного manifest, пропуск rollback при пустом retention-архиве или неудачное восстановление больше не должны разрешать commit.

## Что гарантируется этим пакетом, а что нет

- Изменения в `research_forward.py` проверяют упакованный seed баров по manifest (размер gzip, SHA-256 распакованных байтов, количество байтов и строк) и дают packaged bootstrap seed приоритет над legacy seed из `data/`.
- Курсор исследовательского журнала сверяет SHA-256 всей обработанной части файла, а не только несколько выборочных блоков.
- Маркер `data/retention_archive_state.json` сигнализирует, что цепочка retention-архива уже была инициализирована; при последующем отсутствии доступной копии workflow приостанавливает compaction. Если upload нового архива после compaction не проходит, workflow пытается восстановить все затронутые JSONL из снапшотов, сверяя gzip, размер, число строк и SHA-256. В 5.48.12 commit gate также требует валидный manifest после успешного size-guard и блокирует commit, если compaction отмечен, rollback пропущен и доступного архива нет. После успешного rollback commit пропускается только при staged-файлах строго меньше `100000000` байт; иначе он блокируется. Если size-guard завершился, но manifest повреждён/отсутствует, либо compaction отмечен, а ни rollback, ни непустой retention-архив не подтверждены, commit блокируется.
- Локальные тесты могут проверять синтаксис, алгоритмы и структуру workflow, но не подтверждают фактическую доступность артефактов, GitHub permissions, successful push/rebase, работоспособность BingX VST или реальный runtime удалённого workflow.
- Исследовательские исходы и движения цены не являются доказательством чистой прибыльности реальных сделок. В этом source-only архиве нет runtime `data/`, поэтому финансовую реконструкцию фактических позиций на нём выполнить нельзя.
- Торговые сигналы, формирование зон и рабочее исполнение намеренно не менялись в дополнениях данного forensic-патча. Для утверждения, что они идентичны текущему production `main`, требуется diff с точным production commit.


## Дополнительные исправления версии 5.48.12

- Исправлена фикстура теста переносимости cursor schema v2: она создаёт все обязательные поля и полный SHA-256 обработанного префикса; проверка целостности курсора не ослаблялась.
- В `requirements.txt` добавлен `PyYAML`, используемый shell-интеграционными тестами workflow commit gate.
- Полный локальный набор тестов версии 5.48.12: `445 passed in 31.69s`; recovery/workflow-регрессии: `29 passed in 0.52s`. Локальный интерпретатор — Python 3.13.5; удалённый workflow использует Python 3.11, поэтому удалённый запуск остаётся обязательным.
- Шаги восстановления research seed и записи forward-outcomes не запускаются после провала тестов или проверки изоляции runtime data.
- Сообщение о неудачном восстановлении seed выводится только при фактическом `failure`, а не когда шаг был пропущен из-за ошибки тестов.
- Commit gate явно блокирует сохранение состояния после провала тестов или проверки отсутствия побочных изменений в `data/`; commit step имеет дополнительное условие по результатам обоих шагов.

## Проверка перед применением

1. Получить свежую копию удалённого `main` и сравнить её с этим пакетом.
2. Не удалять и не заменять runtime-файлы: `active_trades.json`, `trades.jsonl`, execution/action journals, event claims, исследовательские журналы/курсор и другие файлы `data/`.
3. Запустить тесты на версии Python, закреплённой в workflow (Python 3.11), затем провести контролируемый workflow-run.
4. Проверить в Actions logs: восстановление retention archive, upload артефакта, запись маркера, безопасную компактизацию, итоговый commit/push, ошибки исполнения и реальное время этапов.

Известные, но не решённые этим пакетом вопросы включают отсутствие явного `workingType` в TP-ордерах, отсутствие общего портфельного лимита риска и невозможность повторно проверить net PnL без runtime исполнения. Список и кодовые ориентиры приведены в `AUDIT_FIXES_RU.md` и `DEEP_AUDIT_RESULTS_RU.md`. Пока эти проверки не проведены, пакет — проверенный локальный кандидат на обновление, а не подтверждённый production deployment.


## Оптимизация исследовательского расчёта (5.48.13)

- `research_forward.py` теперь строит numpy-индекс один раз на общий объект DataFrame и переиспользует его под alias-ключами `SYMBOL|PROVIDER` и `SYMBOL`. Истории разных провайдеров не объединяются.
- Для counterfactual-management один раз на уникальную историю нормализуются OHLC/time-поля и предвычисляется ATR strictly-before-close. Используется прежняя формула: только свечи с `close_time < current.close_time`, 14 последних True Range и прежний warm-up. Для неупорядоченных/невалидных данных остаётся legacy fallback.
- В горячих циклах симуляции убраны повторные pandas Series через `iterrows()`/`iloc`; вместо этого используются tuples и массивы, не меняя порядок проверки стопа/тейка и разрешение внутрисвечной неоднозначности.
- Добавлен лог `[RESEARCH_FORWARD_INDEX]` с количеством alias keys, уникальных DataFrame, строками, временем построения индексов и подготовки counterfactual bars. Следующий реальный запуск позволит измерить экономию каждого участка отдельно.
- Проверка эквивалентности сравнивает полные вложенные counterfactual-результаты старого и нового путей на контрольных наблюдениях, включая строгую временную границу. Полный локальный набор 5.48.13: `449 passed in 21.28s` на Python 3.13.5; точный замер итогового полного GitHub workflow ещё требуется.

Эта оптимизация относится к исследовательской обработке. Она не сокращает вселенную из 330 сканируемых символов, не отключает pre/post сопровождение активных позиций и сверку защитных ордеров, не меняет зоны, признаки входа, SL/TP/BE или правила принятия сделок.
